# GitУчебник

Интерактивный учебник по Git. Чистые HTML, CSS и JavaScript — без сборщиков и зависимостей.

## Структура

```
git-tutorial/
├── index.html          главная: hero + список уроков
├── style.css           общие стили, светлая и тёмная темы
├── script.js           тема, переход к урокам
├── simulator.js        глобальный движок: терминал, gitState, дашборд, сохранение
└── lessons/            страницы уроков
    ├── lesson-1.html   «Введение в Git» — init, status, help
    ├── lesson-2.html   «Добавление файлов» — touch, git add
    ├── lesson-3.html   «Фиксация изменений» — git commit
    ├── lesson-4.html   «Связь с GitHub» — remote add, push
    ├── lesson-5.html   «Ветвление» — branch, checkout
    ├── lesson-6.html   «Слияние веток» — merge
    ├── _template.html  шаблон страницы урока
    └── README.md       соглашения по структуре уроков
```

## Запуск

Просто откройте `index.html` в браузере. Либо, если нужен локальный сервер:

```bash
python -m http.server 8000
```

и перейдите на `http://localhost:8000`.

## Движок `simulator.js`

Вся интерактивность в одном файле и подключается на каждой странице урока:
`<script src="../simulator.js" defer></script>`.

- `gitState` — `{ initialized, branch, branches, user, files, commits, remote }`;
  `user` хранит имя и email из `git config`, статусы файлов:
  `untracked`, `modified`, `staged`, `committed`.
- `renderUI()` рисует все панели: рабочую директорию, индекс, локальные
  коммиты и удалённый репозиторий; имя автора показывается в шапке,
  текущая ветка — бейджем над терминалом.
- Прогресс сохраняется в `localStorage` под ключом `git-tutorial:state`
  в виде `{ version, state, progress }`. При смене `PROGRESS_VERSION`
  сохранение сбрасывается целиком — структура целей изменилась, поэтому
  старый прогресс несовместим.
- Учебные подсказки: если команда в реальном Git молчит (`git add`,
  `git remote add`, `touch`), движок печатает синюю строку
  `[Учебная подсказка]: …` вместо выдуманного вывода Git.
- Учебные цели: у каждого урока есть список доступных команд и целей;
  выполненные цели отмечаются в чек-листе и открывают следующий урок.

## Страницы уроков

Все шесть страниц используют одну вёрстку и общий движок, различаются только
теорией и целями:

- `lessons/lesson-1.html` — представление автора (`git config user.name` и
  `user.email`), `git init`, `git status`; после настройки в шапке появляется
  имя Student;
- `lessons/lesson-2.html` — четыре шага: `touch about.html`, `git status`
  (файл в Untracked), `git add about.html`, `git status` (файл в Staged);
  шаги засчитываются строго по порядку. Главная `index.html` уже существует
  в рабочей директории, а `about.html` создаётся на первом шаге.
- `lessons/lesson-3.html` — первый коммит: `git add index.html`,
  `git commit -m "Add index.html"`, `git status`;
- `lessons/lesson-4.html` — удалённый репозиторий: `git remote add origin …`,
  `git push -u origin master`, симуляция коммита коллеги и `git pull origin master`;
  есть также `git fetch` «скачать без применения»;
- `lessons/lesson-5.html` — ветки: `git branch feature`, `git checkout feature`,
  `git status`; текущая ветка видна в приглашении и бейдже над терминалом;
- `lessons/lesson-6.html` — слияние: `git checkout master`, `git merge feature`;
  появляется коммит с меткой «merge».

Макет — три колонки:

- слева теория (заголовок, пара абзацев, список шагов, подсказка и чек-лист
  «Задачи урока»);
- в центре интерактивный терминал: тёмный фон в обеих темах, моноширинный шрифт,
  строка приглашения `user@git-tutorial:~$`; клик в любом месте блока
  возвращает фокус в поле ввода;
- справа дашборд состояния: три панели-«проводника» (Working Directory,
  Staging Area, Local Repository) со светлым фоном, рамками и иконками файлов;
  закоммиченные файлы помечаются зелёной галочкой, а коммиты показываются
  карточками с оранжевым хешем, сообщением и составом файлов;
- под тремя колонками — широкая панель «Remote Repository (GitHub)»:
  профиль `user / my-git-project` с меткой Public, URL remote и список
  коммитов в стиле GitHub (аватар, автор, хеш, сообщение);
- внизу навигация между уроками.

Страница урока шире главной (`--maxw: 1400px`). На ширине ≤1279px дашборд
уезжает под терминал и раскладывается в три панели в ряд, на ≤900px всё
складывается в одну колонку.

### Команды терминала

| Команда        | Поведение                                                                  |
| -------------- | -------------------------------------------------------------------------- |
| `help`         | список команд, доступных в текущем уроке                                   |
| `clear`        | очищает историю терминала                                                  |
| `git config --global user.name/email …` | запоминает автора; без имени и email `git commit` не выполняется |
| `git init`     | создаёт виртуальный репозиторий; повторный вызов — «Reinitialized existing» |
| `touch <file>` | создаёт пустой файл в рабочей директории (untracked)                       |
| `ls`           | выводит файлы рабочей директории                                           |
| `git add <file>` | переводит файл в `staged` и печатает учебную подсказку                   |
| `git add .`    | переводит все `untracked`-файлы в `staged`                                 |
| `git commit -m "…"` | фиксирует staged-файлы: 7-символьный хеш, запись в `commits`, «[master (root-commit) …]» и статистика; без staged — `nothing to commit` |
| `git remote add origin <url>` | сохраняет URL в `remote.url`; работает только после `git init` |
| `git push` (или `git push -u origin master`) | копирует коммиты в `remote.commits`; без коммитов — `src refspec master does not match any`, без remote — `No configured push destination` |
| `git fetch`    | печатает, что изменения скачаны, но не применены                      |
| `git pull origin master` | переносит новые коммиты из remote в Local Repository и обновляет файлы |
| `git branch [name]` | без аргумента показывает ветки, с именем создаёт новую (учебная подсказка) |
| `git checkout <branch>` | переключает ветку, обновляет приглашение и бейдж ветки |
| `git merge <branch>` | сливает ветку в текущую и добавляет коммит с меткой «merge» |
| `git status`   | до `init` — `fatal: not a git repository…`; после — ветка, зелёный `Changes to be committed`, красный `Untracked files`, а после коммита — `nothing to commit, working tree clean` |
| любая другая   | «Команда … пока не реализована»                                            |

Приглашение меняется по состоянию репозитория:

- до `git init` — `user@git-tutorial:~$`;
- после — `user@git-tutorial:~/project (<ветка>)$`, например `(master)` или `(feature)`.

Enter выводит введённую строку в историю вместе с приглашением и очищает поле.

## Валидация уроков

Страница сообщает свой урок через `<body data-lesson-id="lesson-2"
data-lesson-goals='[…]'>`, а правила лежат в `lessonsConfig` внутри
`simulator.js`:

```js
"lesson-2": {
  version: 3,
  needsInit: true,
  allowed: ["help", "clear", "touch", "ls", "git status", "git add", "git init"],
  blockedMessage: "Недоступно в этом уроке.",
  goals: [
    { id: "touch", command: "touch about.html", label: "Создать файл about.html (команда touch)" },
    { id: "status-untracked", command: "git status", label: "…файл в Untracked…" },
    { id: "add", command: "git add about.html", label: "Добавить файл в индекс…" },
    { id: "status-staged", command: "git status", label: "…файл в Staged…" }
  ]
}
```

- Цели выполняются **последовательно**: засчитывается только следующая
  незакрытая цель, поэтому первый `git status` закрывает шаг 2,
  а второй — шаг 4.
- Команда вне `allowed` не выполняется. В уроке 1 печатается
  `[Система]: Эта команда пока недоступна в этом уроке.`, в уроке 2 —
  красное `Недоступно в этом уроке.` (так `git commit` и `git push`
  остаются за пределами урока).
- Если `needsInit` и репозиторий не создан, при загрузке печатается
  предупреждение `Репозиторий не инициализирован! Вернитесь в Урок 1
  или введите git init.`
- `checkLessonCompletion()` отмечает цели в блоке «Задачи урока», снимает
  `disabled` и класс `btn--locked` с кнопки «Следующий урок» и один раз
  печатает зелёное поздравление.
- При загрузке сохранённый прогресс восстанавливается: кнопка активируется
  сразу, поздравление не повторяется.
- Версия конфигурации хранится вместе с прогрессом. Если она не совпадает
  с `version` урока, сбрасываются только цели этого урока — `gitState`
  остаётся нетронутым. Старый формат с общим массивом целей мигрирует
  в прогресс урока 1.
- `help` показывает только команды, доступные в текущем уроке.
- Урок 6 — пока последний (готовится продолжение): его кнопка «Следующий урок» остаётся неактивной,
  но цели и поздравление работают.

## Сброс прогресса

В футере главной и всех уроков есть неброская красная кнопка
«Сбросить прогресс». Она показывает стандартное подтверждение:

> Вы уверены, что хотите сбросить весь прогресс? Все ваши коммиты и файлы будут удалены.

После «ОК» удаляется ключ `git-tutorial:state` (виртуальный репозиторий и
прогресс уроков), и пользователь возвращается на главную. Тема оформления
не сбрасывается. На главной `simulator.js` тоже подключён — ради этой кнопки.

Старый прогресс с предыдущей структурой целей сбрасывается автоматически:
в сохранении теперь есть `version`, и при несовпадении с `PROGRESS_VERSION`
ключ удаляется при первой загрузке.

Рядом внизу футера — тестовая ссылка «Очистить кэш урока (только для тестов)»:
делает то же самое без `confirm`.

После сброса и перезагрузки урока терминал чистый, в Working Directory виден
только уже существующий `index.html`, Staging и Remote пусты, чек-лист
показывает `0/N`, а кнопка «Следующий урок» снова серая и неактивная.

## Возможности

- Адаптивная главная страница со списком из шести уроков.
- Все шесть уроков доступны и связаны карточками на главной.
- Единый движок и общий прогресс: репозиторий, коммиты и ветки переезжают
  из урока в урок.
- Переключение светлой и тёмной темы с сохранением выбора в `localStorage`
  — выбор действует на всех страницах, включая переходы между ними.
- Учёт системной темы (`prefers-color-scheme`), если пользователь ещё не выбирал вручную.
- Тема применяется до первой отрисовки — без вспышки светлого фона.
- Доступность: skip-link, видимый фокус, `aria-pressed` у переключателя,
  поддержка `prefers-reduced-motion`.

> Если браузер блокирует `localStorage` для `file://`, тема и прогресс
> не запомнятся — запустите страницу через локальный сервер (см. выше).
