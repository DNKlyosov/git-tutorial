Урок 21. VS Code: терминал и интерфейс

NOTE Зачем это нужно?

VS Code не заставляет выбирать между терминалом и кнопками: оба способа работают с одним и тем же Git. Зная, какая кнопка какую команду выполняет, вы свободно переключаетесь между ними и никогда не «застреваете» в интерфейсе.

Введение и установка

VS Code — это мощный редактор, который объединяет в себе терминал и удобный графический интерфейс для Git. Вы можете использовать то, что вам больше нравится.

Скачайте установщик с официального сайта — он сам определит вашу систему, а установка пройдёт с настройками по умолчанию:

Скачать VS Code

Отдельно ставить Git не нужно: он уже есть в системе — им мы пользовались во всех предыдущих уроках. Запустите редактор и откройте папку проекта (File → Open Folder…, на macOS — File → Open…), иначе Git не увидит репозиторий. Терминал открывается внутри редактора по Ctrl + ` (на macOS — Cmd + `) и сразу оказывается в папке проекта.

Настройка связки с GitHub

Перед отправкой кода на GitHub VS Code должен знать, кто вы: без этого Git не подпишет коммит вашим именем и не получит доступ к репозиторию. Авторизоваться можно двумя способами — подойдёт любой.

Способ А — через интерфейс. Нажмите иконку Accounts (человечек) в левом нижнем углу и выберите Sign in with GitHub. Откроется браузер, где вы разрешите доступ, — и редактор запомнит аккаунт.

Способ Б — через терминал. Представьтесь Git, как в первом уроке: git config --global user.name "Student" и git config --global user.email "student@example.com". При первом git push VS Code сам предложит авторизоваться — во всплывающем окне в правом нижнем углу.

Способы дополняют друг друга: git config задаёт имя и почту автора коммитов, а Sign in with GitHub даёт доступ к репозиторию. Надёжнее сделать и то, и другое.

Шпаргалка: терминал против кнопок

Панель Git в редакторе называется Source Control: иконка с тремя кружочками на левой панели (Activity Bar), горячая клавиша Ctrl + Shift + G. Внутри — две группы: Changes (рабочая директория) и Staged Changes (индекс). Действия дублируют друг друга: у каждой команды есть кнопка, а у каждой кнопки — команда.

Действие Терминал Кнопки в VS Code
Проверить статус git status Иконка Source Control: список изменённых файлов сразу на виду
Добавить в индекс git add . Кнопка + рядом с файлом (плюс у заголовка группы — сразу все файлы)
Сделать коммит git commit -m "…" Ввести текст в поле сообщения и нажать галочку ✓ Commit
Отправить на GitHub git push Sync Changes, а при первом пуше — Publish Branch

Когда вы нажимаете кнопку в VS Code, редактор под капотом выполняет ту же самую команду, которую вы ввели бы в терминале. Кнопки — не «другой Git», а обёртка над теми же командами, поэтому и терминал, и панель показывают одно и то же состояние репозитория.

Практика в симуляции

Попробуйте ввести эти команды в терминал (в центре экрана) и посмотрите, как синхронно меняется панель Source Control (справа). В реальном VS Code вы можете делать это как командами, так и кликами — результат будет одинаковым.

  1. git add . — файл уедет из Changes в Staged Changes.
  2. git commit -m "Update from VS Code" — список очистится, а VS Code покажет уведомление Successfully committed.
  3. git push — коммит отправится на GitHub и появится в Remote Repository. 
$ git add .
$ git commit -m "Update from VS Code"
[master 3f9a1c2] Update from VS Code
 1 file changed
$ git push

Кнопки на панели справа не нажимаются — это витрина, которая повторяет состояние репозитория. Представьте, что вы могли бы нажать +, галочку ✓ Commit или Sync Changes: в настоящем редакторе получилось бы ровно то же, что и от команд в терминале. В остальных уроках курса панель работает по-старому — тремя колонками.
