Урок 7. История и изменения

NOTE Зачем это нужно?

Без истории проект — просто набор файлов. Команды ниже показывают, что уже сохранено и что ещё ждёт коммита, — так легче понять, откуда взялась ошибка.

Зачем нужна история

Каждый коммит Git сохраняет вместе с автором, датой и сообщением. Это и есть история проекта: по ней видно, когда появилась строка, кто её менял и почему. Команда git log выводит коммиты от новых к старым.

История нужна, чтобы разбираться в чужом коде и находить причину ошибки. Без неё проект — набор файлов, у которых нет прошлого.

Как увидеть изменения до коммита

Пока правки не закоммичены, git status сообщает лишь, что файл изменён. Команда git diff сравнивает рабочую директорию с индексом и показывает сами строки.

Строки со знаком + — добавленные, Git показывает их зелёным; строки со знаком - — удалённые, они красные.

Так правки проверяют до git add и git commit: если что-то лишнее, файл можно поправить или откатить. Сама команда git diff ничего не меняет — это безопасное чтение.

  1. git log — посмотреть историю коммитов.
  2. git diff — посмотреть изменения в рабочей директории.

В настоящем Git git diff --staged показывает правки, которые уже добавлены в индекс. Здесь достаточно двух команд: git log и git diff.
