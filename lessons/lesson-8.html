Учимся исправлять две частые ошибки: убрать лишний файл из индекса и отменить изменения в рабочей директории.

Урок 8. Отмена изменений

NOTE Зачем это нужно?

Лишний файл в индексе или неудачная правка — обычная ситуация. Git умеет вернуть проект к нужному состоянию, пока коммит ещё не создан.

Как вынуть файл из индекса

Бывает, что в индекс попал лишний файл: добавили test.txt и только потом поняли, что коммитить его не нужно. Коммит ещё не создан — значит, ситуация поправима.

Команда git reset test.txt убирает файл из Staging Area. Сам файл никуда не девается: он возвращается в Working Directory со статусом untracked, и его можно спокойно отредактировать или добавить заново.

Как отменить изменения в рабочей папке

Если файл вообще не нужен, его удаляют с диска. В Git для этого есть git restore test.txt: команда возвращает файл к состоянию из последнего коммита. Для файла, которого в коммите нет, это означает «как будто его не создавали» — он исчезает.

Правило простое: git reset трогает индекс, а git restore — файлы в рабочей директории.

  1. touch test.txt — создать файл.
  2. git add test.txt — добавить его в индекс.
  3. git reset test.txt — вынуть обратно в рабочую директорию.
  4. git restore test.txt — отменить создание файла.

Смотрите на панели справа: после git reset строка test.txt перелетает из Staging Area обратно в Working Directory, а после git restore — улетает и исчезает совсем.
